# 五种条件的一轮流式观察

这里保存教学虚构手册的一次真实 `qwen-flash` 运行：按短材料、长材料、原样重复、改前缀、详细回答的顺序各调用一次，没有重试。运行代码为 `a3898711886307537e9cbc8b7bc2704c34dbae32`。五次均正常 `stop` / `[DONE]`，都回答链接有效期为48小时。

| 条件 | 输入 token | 其中命中缓存 | 输出 token | 首段正文 ms | 流结束 ms |
| --- | ---: | ---: | ---: | ---: | ---: |
| 短材料 | 214 | 0 | 31 | 285.3 | 478.6 |
| 完整长材料 | 4465 | 0 | 31 | 407.3 | 689.3 |
| 原样再发长请求 | 4465 | 4352 | 31 | 283.4 | 509.4 |
| 改最前版本前缀 | 4465 | 0 | 31 | 421.1 | 723.3 |
| 长材料，展开解释 | 4491 | 0 | 286 | 447.0 | 2096.8 |

首段正文计时从本机后端发起模型请求到收到首个非空正文片段，流结束计时到收到 `[DONE]`，均包含网络与服务等待。缓存数属于输入，不额外相加；没有用事件数量推算 token。

本轮原样重复命中了4352个输入 token，改开头前缀后为0。详细回答虽然保留长手册，本轮也为0；相似长前缀不保证隐式缓存命中。第五项同时改变回答要求和输出上限，实际输出从31增至286，不能将耗时差异仅归因于上限或只归因于输出数量。这里只观察到这些请求的实际等待，不据此给出固定提速倍数、稳定延迟或模型性能排名。用量也不是费用账单。

`流式等待-实际请求记录.json` 是页面下载的原始记录，`实际记录核验.json` 保存独立核验结果。核验从原始 SSE 重建回答、首正文与结束时点、用量，并逐字核对重复请求与前缀单处变化。它验证记录一致性，不重发请求，也不能重现当时的缓存和网络状态。

在仓库根目录运行：

```powershell
node evidence/vcm-03-04/核验记录.mjs
```

脚本不需要安装依赖，不读取私密配置，执行后不改写证据。原始记录 SHA256：`71d1aca2c4d0710b42cae01cd0f8384d2420db55e65d33e67c0541a7fe39bb41`。本目录的 Git 属性禁止转换 JSON 换行，保持原始字节。
