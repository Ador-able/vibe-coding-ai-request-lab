# 一次完整任务与一次实际停止

执行代码：`bc6325ef26487866203fe83543be416d4510c676`。从该提交的干净源码归档安装、构建、启动，再在浏览器运行虚构共享书架纪要。两次任务使用 `qwen-flash`，没有重试；第二次在问题文字已开始返回时点击停止。

[原始导出](浏览器实测-完整与停止.json)保留两次任务的输入、实际请求体、供应商SSE、客户端和服务端UI事件、消息快照、结束原因与用量。[核对报告](实测核对.json)及[核对脚本](核对实测.py)可直接检查记录，不会调用模型。

| 观察 | 完整任务 | 实际停止 |
| --- | --- | --- |
| UI事件数 | 57 | 46 |
| 历史进度 | summary → questions → completed | summary → questions → stopped |
| 最终进度片段 | 1条completed | 1条stopped |
| 摘要阶段 | stop，179输入/96输出token | stop，179输入/94输出token |
| 问题阶段 | stop，305输入/61输出token | 已收到半句，finishReason/usage均为null |
| 总消息结尾 | 1次finish | abort，无finish |

完整任务保留一个总start，两个文字段均正常结束，最后得到3条编号问题；摘要结束时先切换阶段，没有提前结束整条消息。历史中的三次进度各自保留当时值，最终消息按同一ID只保留最新状态。客户端与服务端记录的UI事件逐项一致，文字增量可重建各阶段收到的正文。

停止任务保留完整摘要与问题半句，问题阶段记录 `REQUEST_CANCELLED`，没有补写text-end或总finish。未收到的结束原因和用量保持null，不能当成零用量，也不能据此计算该中断阶段的账单。
