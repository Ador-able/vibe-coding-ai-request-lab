# 请求观察室

用一个问题走完“浏览器 → 本地后端 → 模型服务 → 浏览器”。首页每次独立提问，不保存聊天记录；上下文实验页用于对比同一首轮历史的不同保留范围。

发送后展开“查看这次请求”，可以对照页面实际发送的 JSON、后端阶段、请求编号和累计耗时。缺配置时不会出现“请求模型”与“收到模型回复”。浏览器看到后端的 HTTP 状态；模型服务的状态由后端记录，两者不一定相同。

## 运行

使用 Node.js 24.12.0、pnpm 11.20.0。在项目目录执行：

```powershell
pnpm install --frozen-lockfile
if (-not (Test-Path .env)) { Copy-Item .env.example .env }

```

打开 `http://127.0.0.1:4318`。在 `.env` 填写 `API_BASE_URL`、`MODEL`、`API_KEY` 后重启服务。Base URL 从百炼模型 API 控制台复制，同地域、同业务空间的密钥配套使用；不含末尾 `/chat/completions`。本项目使用模型 API，不使用 Coding Plan 的专用端点。型号选择支持非思考文本问答的 Qwen 型号，例如 `qwen-flash` 或 `qwen-plus`。缺配置时会显示错误，不会生成演示答案。

`.env` 仅由后端读取，不加 `VITE_` 前缀、不提交到 Git，也不放进网页。一次调用可能产生模型费用。

## 一次请求里实际装了什么

入口：`http://127.0.0.1:4318/context.html`。沿用上方 Node、pnpm 和模型 API 配置，使用支持 Function Calling 的非思考文本模型，例如 `qwen-flash`。

1. 点击“查询发布时间”。模型先请求 `get_release_info`，本机函数返回一份虚构版本记录，模型再回答发布时间。首轮共两次模型请求。
2. 分别选择“仅本轮问题”“保留聊天文字”“保留完整历史”，发送同一句负责人追问。所有条件使用同一份首轮历史，每次追问只调用模型一次。
3. 展开记录，比较消息、工具定义、工具调用及结果。检查器来自实际发送的请求体；下载的 JSON 保留其原始字符串及实际返回的 `usage`、`finish_reason` 和消息。

三种追问的系统规则、工具定义和参数相同，只改变历史消息。`tool_choice: none` 禁止重新查询；追问结果不会追加到首轮历史。温度固定为 0，不能据此保证模型回答完全一致。若模型猜测、答错或首轮没有遵守“只回答时间”，页面会保留原文，需结合请求记录判断对照是否成立。

工具调用以实际返回的 `tool_calls` 为准；首轮工具阶段接受 `stop` 或 `tool_calls` 结束标记，同时要求一个完整的有效调用。长度截断等未完成结果不会执行工具，原始结束标记仍保存在记录中。

版本资料是本地合成数据，模型返回来自实际 API。本实验不提供模拟成功回退，也不代表模型具有跨请求的长期记忆。历史由本机服务内存持有，浏览器不能回传改写；刷新页面需重新建立首轮，关闭服务后历史清空。每轮最多等待 90 秒，失败会留下已有请求和工具记录；页面不显示请求头、密钥、服务地址或上游原始错误。

## 上下文装得下，不等于用得好

入口：`http://127.0.0.1:4318/quality.html`。本课固定使用 `qwen-flash`，`.env` 中的 `MODEL` 应设为该值；其余模型 API 配置和启动步骤同上。

点击“运行 12 个样例”后，页面串行请求 6 种条件的 A、B 两份合成资料，每次独立请求，不携带此前回答。任务始终是按项目名称与版本号查负责人、冻结日期并引用记录编号。使用相同输出规则、非思考模式、温度 0、`max_tokens: 512` 和 `response_format: json_object`；不提供工具，请求中不传 `tools` 和 `tool_choice`。JSON Object 的支持范围与提示词要求依据[百炼结构化输出文档](https://help.aliyun.com/zh/model-studio/qwen-structured-output)。

| 条件 | 固定变化 |
| --- | --- |
| 短材料 | 16 条，目标记录在第 8 条 |
| 长材料，关键项居中 | 160 条，目标记录在第 80 条；保留短材料全部记录，只增加无关事务 |
| 长材料，关键项首位 / 末位 | 与居中组的文档集合完全相同，只移动目标记录 |
| 相似干扰 | 在居中组中替换 4 条无关记录，换成相近项目名或相邻版本；总条数不变 |
| 真实冲突 | 在居中组中替换 1 条无关记录；同项目、同版本、同确认日期，负责人不同，冻结日期一致 |

每条资料有稳定编号，长度约 121–127 个字符。背景材料由 20 种办公事务模板按地点和批次组合，文档结构相近；实验只观察这个受控提取任务。条件标签与期望结果不进入模型输入。资料数量不是 token 阈值，页面仅显示实际 API 返回的 `usage.prompt_tokens`，没有用其他分词器估算。

评分分别检查状态、负责人、日期与引用。冲突组需要 `status: conflict`、`owner: null`，保留一致日期，并引用双方记录。字段缺失、输出截断和错误引用不判通过；页面始终保留模型原文与实际请求体。表格每行只有两份样例，不把 12 次结果合并为模型准确率。全部通过同样是有效观察；少量合成资料的一次差异不能单独证明原因，也不能代表模型处理所有长材料的能力。

一次完整运行发起 12 次 API 请求，可能收费。请求失败立即停止、保留已有结果，不自动重试，失败项不计入效果判定。每个样例最多等待 90 秒。再次点击“新开始一次”会保留本页旧记录，可从下拉框切换并分别下载；刷新页面会丢失未下载的记录。材料预览不调用模型，也不是模型生成结果。

## 按需读取、压缩和记忆各管什么

入口：`http://127.0.0.1:4318/memory.html`，沿用 Node.js 24.12.0、pnpm 11.20.0 和模型 API 配置，`MODEL=qwen-flash`。10 份材料均为教学虚构，围绕亲子阅读活动雨天能否转入活动室，重点核对容量与费用、批准时限、当前申请状态和清场安排。

主操作按顺序运行三条独立流程，共 5 次模型调用，不携带其他流程的聊天消息：

| 流程 | 真正进入模型的材料 | 调用次数 |
| --- | --- | ---: |
| 全文回答 | 全部原文与同一问题 | 1 |
| 按需读取后回答 | 先用标题、日期、主题与片段选择编号；再只读这些编号的原文回答 | 2 |
| 压缩后回答 | 先按任务整理摘要；最后回答仅使用实际摘要，不偷偷附回原文 | 2 |

请求均为非思考、温度 0。选编号使用 JSON Object，最多输出 256 token；摘要与回答最多输出 1024 token。不提供工具参数，不执行预订、通知或其他业务动作。选取的编号若为空、重复或不存在，流程停止，不自动补选；截断、请求失败保留已有步骤，不自动重试或挑选成功结果。每条流程最多等待 90 秒。

表格直接汇总各步 API 返回的 `usage.prompt_tokens` 与 `completion_tokens`，分别列最后回答的输入、整链输入、整链输出及输入输出合计。任何一步用量缺失，合计显示未完整返回。token 数不等于费用；最后回答输入更短也不能证明整条流程更省。实际输入、原始输出及用量可逐步展开或下载，回答语义由读者对照来源核查，页面没有自动通过判定。

跨会话区使用一份固定的人工教学便笺，明确区分已确认条件、未决事项、下一步和来源日期。勾选核对后才保存到已忽略的 `artifacts/memory-task-note.json`。重新启动服务或刷新页面后可以重新读取；“用便笺开始新会话”仅发送便笺、它指向的原文和当前问题，另调用模型一次，不携带旧消息，也不修改模型权重。来源编号可实际打开对应原文。这份便笺不是模型生成结果，也不与前三条流程作相同总成本比较，先前任务与人工核对成本未计入。

重复比较保留本页旧记录，刷新前应下载；已保存便笺则继续留在本机文件。要实测服务重启读取便笺，可在保存后停止 `pnpm dev` / `pnpm start`，按同一命令重启，再打开实验页。Git 标签恢复不会恢复或清除该 ignored 便笺文件。

## 长输入为什么影响等待和费用

入口：`http://127.0.0.1:4318/latency.html`。沿用 Node.js 24.12.0、pnpm 11.20.0 及上述私密模型配置，`MODEL=qwen-flash`。依次点击五个条件，每次点击调用一次，不自动重试；这是一轮受控观察，不是性能排名。

| 条件 | 与完整长请求的区别 |
| --- | --- |
| 短材料 | 只使用完整手册中的 M21，保留同一事实与问题 |
| 完整长材料 | 40 条人工编写的虚构产品说明，问题放在资料后 |
| 原样再发长请求 | 请求体字符串与完整长材料逐字一致 |
| 改最前版本前缀 | 只将系统消息最前的实验版本 A 改为 B，其余不变 |
| 长材料，展开解释 | 同一手册和问题，末尾改为约 350 字的说明要求，输出上限改为 512 |

请求固定非思考、温度 0，前四项输出上限 96 token。使用 `stream:true`、`stream_options:{include_usage:true}`，不传工具或显式缓存参数。每次最多等待 90 秒，连接关闭会取消上游请求；错误、截断及实际片段均保留，不把不完整回答显示为成功。

首段正文时间从本机后端发起上游 `fetch` 算起，直到收到第一个非空 `delta.content`。角色块、空文本和用量块不计入。流结束时间采用同一起点，到收到 `[DONE]` 或上游正常 EOF；没有完整结束标记的回答仍报错。一个 SSE 数据事件可含多个 token，时间记录包含网络与服务调度影响，不代表 GPU 预填充耗时或精确的逐 token 间隔。

用量仅读取真实 API 的 `usage`；未返回显示“未提供”，缓存字段缺失也不能当成 0。`prompt_tokens_details.cached_tokens` 是输入 token 的子集，不重复相加。北京地域的 `qwen-flash` 支持隐式前缀缓存，至少 1024 token 的公共前缀具备条件，但不保证命中。不得根据“原样再发”按钮名称直接判断是否命中，需看实际返回。输入、缓存输入与输出采用各自适用的模型、地域价格，这里不伪造统一 token 单价或实时账单。

每条记录包含实际发给 `fetch` 的同一请求体字符串、正常响应的原始 SSE `data`、接收相对时间、`usage`、`finish_reason` 和完整拼接正文，不包含认证头或服务地址。服务商错误原文不公开，避免泄露账户信息。JSON 下载保留本页所有尝试，重跑不会清除之前记录；刷新前应下载。若浏览器与本机服务断开，只能保留已到达浏览器的部分，缺少完整记录会明确标出。

实现位于 `src/latency/`：`materials.ts` 定义对照材料与请求，`model.ts` 计时并记录上游流，`sse.ts` 使用 `eventsource-parser` 4.1.1 处理字节解码及 SSE 边界，`routes.ts` 将实际文本增量传给页面，`contract.ts` 读取可用的用量，`main.ts` 显示与下载观察结果。没有修改原有请求实验的行为。

## 人在环路：活动文字共写

入口：`http://127.0.0.1:4318/collaboration.html`。沿用 Node.js 24.12.0、pnpm 11.20.0 与 `MODEL=qwen-flash` 配置。活动资料均为教学虚构：周六14:00—16:00、社区图书馆一层、30个家庭名额、亲子共同阅读、带一本愿分享的书、免费，报名方式尚未提供。

先编辑任务，生成两种宣传方向；读完原始回答后，自由输入自己的选择、经验、补充或纠正，再让模型继续共写。页面不替读者判断哪种方向更好，不自动评分，也没有对外发布、图片生成或视频剪辑。最新回答可复制，之前完整回答可展开回看。

页面保存成功的用户输入和助手原文，每次把全部成功对话与本轮输入交给后端，由后端附加活动资料并构造消息角色。没有摘要或自动丢弃旧消息。失败和截断的实际记录单独保留，不加入后续成功对话；输入保留，可自行修改后再提交。浏览器刷新会清空对话，刷新前可下载全部尝试、完整请求、原始响应和真实用量。本机服务重启不会清除仍开着的页面对话。

每次提交仅调用模型一次，非思考、温度0、最多输出1536 token，90秒超时，不自动重试。输入最多6000字符；完整请求超过128KB会明确拒绝，不静默删减历史。对话增长会增加输入用量。下载记录包含输入与回答，不包含私密请求头。

调用链为 `src/collaboration/main.ts` → 独立 `/api/collaboration/turn` → `sendRecordedRequest`。活动资料在 `scenario.ts`，成功历史规则在 `contract.ts`。沿用现有依赖，没有新增框架或会话数据库。
