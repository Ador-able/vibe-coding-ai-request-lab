# 请求观察室

在同一个页面入口完成上下文、人工反馈、结构化输出和流式消息实验。材料均为教学虚构，点击运行会调用真实模型 API，可能产生费用。

## 首次准备

沿用课程首次准备的 Node.js，从 [GitHub 仓库](https://github.com/Ador-able/vibe-coding-ai-request-lab) 获取项目，双击“启动实验.cmd”即可。

打开 [请求观察室](http://127.0.0.1:4318)。在“模型设置”填写 OpenAI 兼容接口地址、API Key 和自选模型；上下文实验需要模型支持工具调用。Base URL 使用模型 API 地址，不含末尾的 `/chat/completions`。

配置只需保存一次。所有实验页共用，保存后立即生效；刷新页面、重启服务或重新下载项目后仍可继续使用。已有密钥显示为掩码，留空保存会保留原值。

## 以后做实验

双击“启动实验.cmd”，打开 [请求观察室](http://127.0.0.1:4318)，用顶部“实验”切换页面。服务正在运行时直接切换。保持启动窗口打开，结束时按 Ctrl+C。

| 实验 | 页面 | 操作 |
| --- | --- | --- |
| 独立提问 | `/` | 输入问题，发送后展开请求记录。 |
| 上下文对照 | `/context.html` | 先查询发布时间，再依次运行三种追问条件。首轮调用 2 次，追问各 1 次。 |
| 材料对照 | `/quality.html` | 运行 12 个样例，对照事实与引用；结果不代表整体准确率。 |
| 按需读取与记忆 | `/memory.html` | 比较全文、按目录选原文、先摘要再回答；完整比较调用 5 次。 |
| 等待与费用 | `/latency.html` | 按顺序运行五种条件，比较等待时间和实际用量。每项调用 1 次。 |
| 结构化输出 | `/structured.html` | 用三种输出方式提取同一份纪要，对照原文核查负责人和日期。每次调用 1 次。 |
| 流式消息 | `/streaming.html` | 生成摘要和待确认问题，观察事件顺序；也可在生成中停止。完整任务调用 2 次。 |
| 活动文字共写 | `/collaboration.html` | 提交任务，选择方向或纠正事实，再观察下一轮是否采用反馈。每轮调用 1 次。 |
| 方案与取舍 | `/decisions.html` | 生成两份方案，结合已知事实判断理由、取舍与待确认项。调用 1 次。 |
| 人工反馈 | `/feedback.html` | 确认规则，比较订单在有规则和无规则时的回答。每次调用 1 次。 |

结构化输出需要服务与模型支持严格 JSON Schema；默认沿用已选模型，需要时在“其他实验模型”里选择相应型号。向量实验使用支持嵌入的模型，在同一处设置一次。

## 保存结果与失败处理

完成比较后，展开请求记录并下载 JSON。下载保留实际发送的正文与回答，不含认证头或密钥。页面中的尝试记录通常在刷新后清空；上下文实验刷新后需重新查询首轮，服务重启会清空内存历史。确认保存的便笺和反馈规则保存在项目的 `.local-data` 目录。

请求失败会显示错误并保留已经取得的片段或记录，不自动重试。修改配置后直接重新运行；模型权限或额度错误需到模型服务商处处理。停止服务后再启动，不会恢复正在生成的请求。

本机课程实验共用已保存设置。服务只监听 `127.0.0.1:4318`。如果提示端口占用，先结束正在运行的请求观察室。

## 其他本机实验共用配置

需要在另一个实验目录启动 Node.js 程序时，可使用配置入口。先完成目标项目自己的依赖安装和构建，再从请求观察室目录运行：

```powershell
node scripts/run-lab.mjs "D:/练习/动作审批" dist/approval-cli.js
```

此命令把已保存的地址、密钥和型号交给目标进程，不必再填配置。目标程序照常接收键盘输入、显示结果并返回自己的退出码；后续参数直接写在入口文件后。运行 TypeScript 入口时，目标项目需已安装 `tsx`。

<details>
<summary>需要修改源码时再做开发准备</summary>

沿用课程首次准备的 pnpm，在项目目录运行一次：

```powershell
pnpm install --frozen-lockfile
```

开发时运行 `pnpm dev`，修改会直接反映在页面上。完成修改后运行 `pnpm build`，再双击“启动实验.cmd”使用生成的程序。

按改动需要运行 `pnpm check`、`pnpm test`。测试中的本地响应只验证协议与失败处理，不代表真实模型效果。

</details>

## Git 节点

日常观察使用 main。原有每课 start/end 标签保留源码起点与完成点，课程开发步骤使用指定节点。做错时先在自己的分支提交当前改动，再从本节节点建立新练习分支；进入下一节时同样从下一节起点建立分支。运行历史节点时，让编码助手通过 scripts/run-lab.mjs 将已有设置交给对应入口。
